# 2026-08-17

## Favicon: give the app a real icon instead of a 404

**What we did** — Added `public/favicon.svg` and linked it from `index.html`.
Cosmetic only — no source, dataset or architecture change, so no diagram update
was needed.

**The reason** — Driving the running app in a headless browser surfaced a console
error on every page load: `GET /favicon.ico 404`. There was no icon file anywhere;
`index.html` declared no `<link rel="icon">`, so the browser fell back to the
default `/favicon.ico` path and missed. Worth noting for anyone probing this in
dev: curling `/favicon.svg` returned `200` _before_ the file existed, because
Vite's dev server answers unknown paths with the SPA fallback (`index.html` at
`content-type: text/html`). A status code alone doesn't prove an asset exists —
check the body.

**How it was solved** — The icon is the map in miniature: one vivid family root
with five subgenres radiating out on the app's `--bg` (`#08080c`). Colours are
derived from `src/graph/colors.ts` rather than picked by eye — satellite hues are
the first five steps of the golden-angle sequence, and each satellite sits one
step down the depth ramp from the root (saturation 78→67, lightness 52→58), so the
icon fades outward the way real nodes do. Only `subgenre of` edges are drawn, per
the edge rule. Verified at 16/32/64px: legible as a distinct cluster at tab size,
and the dark rounded plate keeps it readable on a light tab bar. Confirmed in the
browser that the load is now clean — zero failed requests, zero console errors —
and that `dist/favicon.svg` ships in the production build.
