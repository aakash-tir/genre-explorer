# 2026-10-09

## CI: lean on Actions minutes — PR-only, path-filtered

**What we did** — `ci.yml` (`verify`) now runs on pull requests (and by hand via
`workflow_dispatch`) only, and only when a file it reads changed: `src/`, `tests/`,
`scripts/`, `public/`, `index.html`, the npm manifests, the TypeScript/Vite/Vitest/
ESLint/Prettier configs and `.github/workflows/`. The `push: main` trigger is gone, and
every PR run cancels the previous one for the same branch. The graph/diagram refresh
moved from "after every merge, in a follow-up PR" to "in the same PR, before merge".
`deploy-pages.yml` (push to `main`) and `refresh-data.yml` (daily cron) are unchanged.
Workflow and docs only — no architecture change, so no diagram update.

**The reason** — The GitHub account ran out of Actions minutes. Every change ran the
full suite twice (once on the PR, again on the push to `main` that merged the same
code), docs-only PRs ran the full suite, and the post-merge graph refresh was its own
PR that ran it a third time.

**How it was solved** — `on.pull_request.paths` lists the inputs of `verify`; there is
no change-detection job, since that would itself cost a billed minute. `public/**` is
included so the daily dataset PR still gets `verify`, which its auto-merge waits on.
`verify` remains a required check on `main`, so a docs-only PR (which starts no CI) gets
it by dispatch: `gh workflow run ci.yml --ref <branch>`. Documented in `.claude/CLAUDE.md`,
the PR template and `docs/runbooks/ci-and-branch-protection.md`, including the caveat
that `prettier --check .` covers `*.md`, so docs-only PRs should be format-checked
locally.

## Dataset refresh paused; `verify` no longer a required check

**What we did** — Disabled the `Refresh dataset` workflow on GitHub (no more daily
04:00 UTC runs until the owner turns it back on), and changed `main`'s branch protection:
the `verify` required status check is gone, and a PR is still required (0 approvals,
admins included). Docs updated to match: `.claude/CLAUDE.md`, `.claude/progress.md`,
`docs/runbooks/ci-and-branch-protection.md` (also corrected two out-of-date parts:
protection is active since the repo went public, and the cron is daily, not weekly).

**The reason** — The owner asked to pause the dataset updates for now, and to drop the
required check: with path-filtered CI a docs-only PR never gets `verify`, so it could
only merge after dispatching CI by hand.

**How it was solved** — `gh workflow disable "Refresh dataset"` (a GitHub setting, so it
survives until `gh workflow enable`), then `DELETE .../protection/required_status_checks`.
That check had been the only thing blocking direct pushes to `main` server-side, so a
PR requirement with 0 approvals was added to keep `main` PR-only. Caveat recorded where
the refresh is described: its `gh pr merge --auto` no longer waits for `verify`, so
re-add the check or make the workflow wait before re-enabling it.
