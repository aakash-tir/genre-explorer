## Sticky selection: the panel and preview survive map browsing

**What we did.** Split the map's "focus" into two independent pieces: the SELECTION
(which genre the panel shows, `state.focusId`, in the URL) and the FAN (the
fan/dim exploration view, ephemeral `fanOpen` state). Empty-space clicks now
collapse only the fan; the selection — its panel, its playing preview, its ring
outline — persists until a DIFFERENT genre is clicked. Clicking the selected genre
toggles its fan.

**The reason.** Owner request: "if I'm listening to something keep it on the right
side until I select something else." Previously an empty-space click (easy to do
while panning) cleared the focus, unmounting the Deezer widget mid-song.

**How it was solved.** `fanOpen` gates the fan overrides, ring clearance, dimming,
spokes-only edge mode and the LOD focus reveal in GraphCanvas; the selection ring
draws whenever a genre is selected (dust-sized if the node is below the LOD cutoff)
so the listening genre stays marked while browsing. The canvas now reports raw hits
and App owns the click semantics. Debugging note: the change initially appeared
broken in headless screenshots — stale HMR handlers on the canvas — and was
confirmed working with a fresh page load plus draw-time instrumentation.

## Went public, real branch protection, and the site is deploying to GitHub Pages

**What we did.** Swept the full git history for leaks, made the repo public, turned
on real server-side branch protection, and set up automated deployment to GitHub
Pages at <https://aakash-tir.github.io/genre-explorer/>.

**The reason.** Owner goal: deploy to a website; owner approved public visibility
after a leak check. Going public also unlocked two things that were paid-only on
private repos: server-side branch protection (closing the documented
red-CI-can-merge gap from 2026-08-04, exploited by accident in PR #4) and GitHub
Pages — whose only disqualifier in the hosting research was the private-repo
paywall, and which unlike Cloudflare needs no manual dashboard step.

**How it was solved.** Scan: all 44 revisions checked for key material, secret-ish
filenames, email addresses and absolute paths in content — clean (the project has
no secrets by design). One finding surfaced to the owner: 25 commits carry their
personal email in author metadata; they chose to accept it, and local git config
now uses the GitHub noreply address for future commits. Protection: required
status check `verify` (strict), enforce_admins, no force pushes. Hosting: Pages
set to workflow builds; the deploy workflow builds with `--base=/genre-explorer/`,
ships `404.html` as the SPA fallback for deep links, and the app gained pure
`stripBase`/`withBase` helpers plus BASE_URL-aware data URLs so one bundle works at
both the domain root and the sub-path. Cloudflare Pages is documented as fallback
in `docs/runbooks/hosting.md`.

## Hover polish: nodes swell slightly under the cursor

**What we did.** Hovered nodes now draw at 1.18x radius, with the outline ring,
label and pointer cursor tracking the enlarged size (focus ring included when the
focused node itself is hovered).

**The reason.** Owner request — hover feedback was a ring only; the slight swell
makes the map feel tactile and confirms what a click will hit.

**How it was solved.** A `HOVER_SCALE` factor applied at draw time in GraphCanvas;
no layout or hit-test change (the hit slop already exceeded the growth). Cosmetic —
no diagram update needed.
