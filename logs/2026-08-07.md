## Post-merge chores for PR #3: knowledge graph refresh + first architecture diagram

**What we did.** Ran `graphify update .` (390 nodes, 554 edges, 29 communities) and
created `docs/architecture/architecture-diagram.html` — the project's first
architecture diagram, since PR #3 was the first merge to introduce real structure.

**The reason.** The post-merge rule in `.claude/CLAUDE.md` requires both artifacts to
track every architecture-changing merge, and milestone 2 changed the architecture
substantially: the pipeline went from a single stub to eight components (HTTP
helper + cache, stages 1–3, build-graph, layout, emit) with two external services in
active use.

**How it was solved.** Manual layout per the architecture-diagram skill's design
system: build-time region (external services → rate-limited cached HTTP → stage
column → emitted artifacts) above the runtime region (loader → pure rules → React
shell), with dashed strokes distinguishing planned components (stages 4–6,
ListenBrainz, Deezer, detail files, Cloudflare Pages) from built ones. Render
verified with a headless-Chromium screenshot; three sublabels that overflowed their
boxes were tightened and re-verified. This entry is docs-only apart from the diagram
itself.

## Fix: PR #4 merged red — prettier failure masked by a piped exit code

**What we did.** PR #4's `verify` check failed on CI, but the merge went through
anyway; this PR reformats `docs/architecture/architecture-diagram.html` with
Prettier so `main` is green again, verified locally and by re-screenshotting the
diagram (render unchanged).

**The reason.** Two failures stacked. The diagram HTML was committed without
running Prettier over `docs/`, so `format:check` failed CI. Then the merge command
chained `gh pr checks 4 --watch | tail -2 && gh pr merge` — piping to `tail` made
the chain's exit status `tail`'s success, not the check result, and because `main`
has no server-side protection (the known gap from 2026-08-04: branch protection is
a paid feature on private repos), nothing on GitHub's side blocked the red merge.

**How it was solved.** `prettier --write` on the diagram, full `npm run verify`
locally before pushing, and check status is now read from `gh pr checks`' own exit
code rather than a pipeline tail. The structural fix remains the one already in
`docs/future.md`: make the repo public or upgrade so red CI can actually block a
merge.
