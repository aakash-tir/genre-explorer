# 2026-08-06

## Milestone 2: the real MusicBrainz genre tree replaced the sample dataset

**What we did.** Built pipeline stages 1–3 plus layout and emit in
`scripts/build-dataset/`, ran the full ~80-minute scrape against MusicBrainz, and
committed the first real `public/data/graph.json`: 912 genres, 1,657 edges (733 drawn
`subgenre` tree edges, 815 `influence`, 109 `fusion`), 179 family roots, 242.8 KB —
under the 400 KB budget. A previous attempt at this run had died mid-way in an internet
outage and left nothing on disk, so this was a from-scratch rebuild; the new pipeline
disk-caches every response under `.cache/build-dataset/`, so the next interruption
resumes instead of restarting.

**The reason.** The map cannot exist without the tree, and the tree only exists in
MusicBrainz's HTML — `inc=genre-rels` returns 200 with no relations (verified
2026-08-04, re-confirmed today). The parser is therefore fixture-tested over four saved
real pages (grunge, dubstep, alternative dance, acholitronix) with a
`looksLikeGenrePage` tripwire, because the dangerous failure is an error page or
redesign parsing as "genre with no relations" and silently emptying the map. Each
relation is read from both pages it touches, so one malformed page cannot lose an edge.

**How it was solved.** Stage 1 pages `/ws/2/genre/all` (JSON) for 2,184 mbids; stage 2
scrapes each genre page at 1 req/s through a single rate-limited, retrying, disk-cached
HTTP helper; stage 3 reads release-group tag counts from one search query per genre.
`build-graph.ts` (pure, unit-tested) applies the threshold and builds the tree; seeded
`d3-force` at a fixed tick count bakes byte-identical coordinates; emit Zod-validates
and enforces the sharp-drop guard against the committed dataset.

Decisions made from the real distribution, closing two "Decisions still open" items:

- **Threshold: 50 release-groups**, keeping 912 of 2,184 (target band was 800–1,200).
  Insensitive near the cut — raising it to 100 would still keep 771 — so the provisional
  value stood.
- **Orphans stay floating family roots** — no synthetic "music" node. Real numbers: 179
  roots, but 131 are isolated singletons, which creates a new colour-scheme question
  recorded in `docs/future.md`.
- **Multi-parent children** (4 of them) keep their most popular parent as the drawn
  edge; the other parent relations are demoted to associative `influence` so
  focus-reveal still surfaces the child under every parent, and no second line is ever
  drawn.

Also fixed en route: the sample dataset's MBIDs turned out to be fabricated (its
"grunge" id is really dubstep's), which mattered once fixtures were fetched by MBID —
one more reason the sample needed replacing. `tests/fixtures/` was added to
`.prettierignore` since saved MusicBrainz pages must stay byte-exact.

No architecture-diagram update needed beyond what the PR itself changes: the pipeline
components already existed in the diagram as planned stages; verify at merge time.
